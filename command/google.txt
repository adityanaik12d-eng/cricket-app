Part 5: Key UX Patterns to Adopt
Real-Time Update Indicators:
Subtle pulse animation (green dot) in the scorecard tab when a live ball event lands.
Transient highlight on the batter/bowler row currently active on the delivery.
Pull-to-Refresh & Optimistic Commentary:
Commentary utilizes optimistic client updates during manual ball entry, instantly verified via incoming server-ack.
Standard pull-to-refresh on tournament standings and classified feeds with background data fetch.
Offline/Cached State Handling:
Scoring engine operations persist into local IndexedDB storage before network synchronization to safeguard against field connectivity drops.
Read-only users receive an offline banner indicating cached timestamp ("Viewing cached scorecard from 2 mins ago").

Part 6: Technical Considerations
1. WebSocket vs. Polling for Live Updates
Hybrid SSE / WebSocket Architecture:
Match Scorers (Bidirectional): WebSocket connection with TLS to guarantee fast delivery of ball submissions and immediate conflict rejection.
Viewers (Unidirectional): Server-Sent Events (SSE) or Redis-backed WebSockets channeled through a global CDN edge. Matches falling into non-live states fallback to standard HTTP stale-while-revalidate polling at 60-second intervals.
2. State Management Strategy
Use Zustand or Redux Toolkit:
matchStore: Holds current live ball events, active bowler/batsmen, current partnership, and live scorecard.
tournamentStore: Holds league standings, filtered leaders, and schedule trees.
Local UI preferences (active sub-tabs, filter selections) persisted in localStorage.
3. Caching Strategy
Edge Caching: Cache completed scorecard API routes at the CDN edge with Cache-Control: public, s-maxage=31536000, immutable.
Live State Invalidation: Live matches utilize an in-memory Redis layer with pub/sub that broadcasts state deltas (ball diffs) rather than refetching the entire match payload on every delivery.
4. Performance with 100+ Balls in Commentary
DOM Virtualization: Implement @tanstack/react-virtual for the ball-by-ball commentary list to guarantee 60fps rendering across mid-range mobile devices regardless of the total over count (e.g. 50-over ODIs with 600+ events).
Memoize each delivery row component using React.memo keyed by the unique ballId.
